# bmo-text

채팅방, 콘솔, 아카이브가 읽는 방식 그대로 마크다운과 텍스트를 읽고 쓰는 기반 라이브러리입니다. 마크다운을 Telegram의
HTML과 일반 텍스트로 바꾸는 변환, 마크업의 구조 검사, 접기와 메시지 분할, 본문 속 웹 주소, 대시 재작성, 금지어 용어집에
대한 텍스트 검사, 답변 상한, 마크다운 문서의 구조, 검색 결과의 구조 행, 번역기에 넘기는 텍스트 조각, 그리고 HTML
페이지를 행 단위로 읽는 기능을 담고 있습니다. 이 읽기 로직은 Rust 크레이트에 한 번만 작성되며, TypeScript 패키지는
그 크레이트를 WebAssembly로 빌드한 것으로 Bun, Node, 브라우저 어디서든 import 시 동기적으로 로드됩니다. 길이는 `chars`라는
이름이 붙지 않은 한 UTF-16 단위로 세고, 공백과 trim은 JavaScript를 따르므로 같은 입력에 대해 두 쪽이 같은 답을 냅니다.
크레이트의 바이너리를 `bmo-text mcp`로 실행하면 MCP 서버가 되며, `bmo-text` 플러그인을 받은 코딩 하네스는 이를 통해
순수 읽기 기능을 호출합니다.

| 폴더 | 내용 |
|---|---|
| `docs/` | 설계, 공개 API, 경계, 라이브러리가 무엇으로부터 만들어졌는지에 대한 목록, 기반 분리 계획, 개인 정보 규칙 |
| `src/` | Rust 크레이트 `bmo-text`의 소스. 매니페스트는 루트에 있습니다 |
| `tests/` | 크레이트의 테스트와, 저장소 자체의 구조를 지키는 저장소 테스트 |
| `package/` | TypeScript 패키지 `bmo-text`: 크레이트의 WebAssembly 빌드 위에 놓인 모듈, `wasm/`의 빌드 결과, 그리고 테스트 |
| `cases/` | 크레이트와 패키지가 함께 지켜야 하는 사례. 모듈마다 파일 하나 |
| `plugin/` | 하네스 플러그인 `bmo-text`: 매니페스트, MCP 서버 설정, `bmo-text` 스킬 |

이 라이브러리는 레지스트리 패키지 외에는 아무것에도 의존하지 않으며, HTTP 서버나 배포가 없습니다. 사용하는 쪽은
크레이트를 경로나 git으로, 패키지를 의존성으로 가져오고, 스스로 정할 것들을 넘겨줍니다. 독자가 보는 문구, 영어 정책,
용어집의 경로가 그렇습니다.

개인 정보는 코드, 테스트, 문서, 커밋에 넣지 않습니다. `docs/PERSONAL-DATA.md`에 그 규칙과 이 저장소가 규칙을 지키도록
하는 검사가 적혀 있습니다.

이 라이브러리는 MIT 라이선스로 배포되며, 전문은 `LICENSE`에 있습니다.

검사와 테스트는 `testbed.toml`에 선언되어 있고, 실행할 명령은 `CLAUDE.md`에 적혀 있습니다.
